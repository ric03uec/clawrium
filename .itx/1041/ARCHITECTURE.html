One SSH identity
for every agent.

The control machine creates and retains each agent’s keypair. Shared Ansible provisioning installs the same identity into that agent user’s SSH directory; sync fills gaps without rotating established keys.

02 /

System boundary

One per-agent identity crosses a host-management connection.

Local · control machine

Generate & retain

Clawrium owns the desired identity. Key generation and consistency checks are shared across agent types.

Agent key store

core/keys.py

Ed25519 keypair scoped by immutable host key ID + agent name. A separate root prevents host reset from deleting it alongside xclm_ed25519.

~/.config/clawrium/agent-keys/<host-key-id>/<agent>/id_ed25519{,.pub}
private 0600 · directories 0700

OS dispatcher

playbook_resolver.py

Selects the shared Linux or macOS provisioning playbook. A read-only remote preflight runs before first generation; Ansible copies controller file paths without putting key bytes in metadata or events.

Ansible / SSH
uses existing host management key
Remote · target host

Install & verify

A shared system-level playbook owns the filesystem work, regardless of agent implementation.

Agent user’s SSH directory

Linux / macOS

Recheck destination before copying. Set ownership and restrictive ~/.ssh / private-key permissions; reject unrelated existing keys.

Linux: /home/<agent>/.ssh/id_ed25519{,.pub}
macOS: /Users/<agent>/.ssh/id_ed25519{,.pub}

Other agents stay separate

isolation

Agent B on the same host receives its own pair in its own user home. Neither identity becomes the management SSH credential.

Boundary ruleRemote writes go through Ansible. Resolve the agent home as /home/<agent> or /Users/<agent>, never ansible_user_dir. Linux uses the agent group; macOS uses staff. Paths and names above are the proposed layout, subject to implementation review.
03 /

Reconciliation rules

The same decision on install and every real sync.

No keypair anywhere

Preflight finds no local or remote pair: create on the controller, then install into the agent home. Also backfills an existing agent.

Create + provision

Matching pair exists

Leave it untouched. Install, configure, restart, and repeated sync do not rotate this identity.

No-op

Remote copy missing

Restore absent files from the controller. A remaining component must first match the controller pair.

Repair without rotation

Partial or conflicting

Local partial, remote conflict or orphaned remote identity: stop with a recovery hint. Never overwrite or silently rotate.

Stop + explain

Walk through an operation

Select a scenario to see the proposed flow.

These are design examples, not live commands. Each scenario starts with the controller checking its own key store and the remote agent home; unsafe remote state fails before a new identity is minted.

Fresh install

The agent user is created before the shared key provisioning step.

$ clawctl agent create maurice --type hermes --host labbox Created · agent identity installed

What happens

  1. Agent install creates the user on labbox.
  2. Read-only preflight checks the agent’s SSH destination.
  3. Controller generates a unique pair, then shared Ansible copies it with safe ownership and modes.
  4. Installation becomes successful only after provisioning succeeds.

Agent details, conceptually

Read the public key from the controller’s store. Do not persist private bytes in hosts.json or emit them through CLI output, events, errors, or logs.

$ clawctl agent describe maurice

Name:            maurice
Type:            hermes
Host:            labbox
SSH public key:  ssh-ed25519 <illustrative-public-key> clawrium
SSH private key: [REDACTED]

The existing host reset is separate and keeps agent identities. A future explicit agent reset would own rotation; there is no agent reset or key-management command today.
